Chamber Devices

Every device is a full replica of the record. This console shows how yours is keeping in step — and pairs it directly with another cousin's browser, server or no server.

Guarantee: if any one replica survives, everything survives.

This replica

Replication status

Peer-to-peer

Pair with another cousin

With the Cloudflare relay configured, browsers on this page pair with each other automatically — nothing to do. The invite codes below are the zero-infrastructure path: they carry the WebRTC handshake by hand (paste into any chat), and after that the connection is direct between the two browsers. State flows peer to peer either way.

Side A — invite

Create an invite

  1. Create the invite and send the code to your cousin.
  2. They paste it on their device and send back an answer code.
  3. Paste the answer below — the channel opens and both sides backfill.

Codes are single-use and expire in about a minute — paste promptly.

Side B — answer

Accept an invite

Received an invite code? Paste it here, then send the generated answer code back the same way.

Once your cousin pastes this, the channel opens by itself.

Custody of the record

Export, import, recover

Export the log

A single JSON file containing every operation this replica holds. Archive it, email it, print it and frame it.

Import a log

Merge an exported file into this replica. Duplicates are ignored; only genuinely new history lands.

Erase this device

Wipes this replica only. Every other device keeps the record, and this one can rejoin and recover it all later.

The recovery guarantee, spelled out. State lives in an append-only operation log, and every replica holds all of it. A brand-new browser that pairs with any single up-to-date peer — via relay, invite code, or an imported file — receives the complete history and folds it into the identical chamber state. There is no primary copy to lose.
